## 📌 О проекте (для разработчиков)

**CacheCleaner** — это консольная утилита для очистки временных файлов и кеша на Windows и Linux, написанная на **C++17**. Проект использует гибкую систему пресетов на основе JSON и поддерживает переменные окружения для динамического формирования путей.

Основная цель — предоставить безопасный и настраиваемый инструмент очистки, который можно легко расширять и поддерживать. Проект разработан как учебный, но следует стандартам, приближенным к промышленной разработке.

## 🧱 Архитектура и структура проекта

Проект организован следующим образом (на основе директорий репозитория):

```
CacheCleaner/
├── .github/workflows/      # CI/CD пайплайны (GitHub Actions)
├── dependencies/           # Внешние библиотеки и зависимости (сабмодули)
├── docs/                   # Документация, лицензия, презентации
├── header/                 # Заголовочные файлы (.h/.hpp), синхронизированные с типами
├── include/                # Публичные заголовки и общие включения
├── src/                    # Исходный код (.cpp) — основная логика
├── CMakeLists.txt          # Главный файл сборки CMake
├── setup.iss               # Скрипт INNO Setup для создания установщика
├── TODO.MD                 # Актуальный список задач и статус разработки
├── version.txt             # Текущая версия проекта
└── readmeDEV.md            # Этот файл (документация для разработчиков)
```

### Ключевые компоненты

- **`src/`** — содержит реализацию основных модулей: парсинг JSON, работа с файловой системой, логика очистки, обработка переменных окружения.
- **`header/`** — заголовочные файлы, соответствующие модулям из `src/`. Все типы синхронизированы (см. коммиты).
- **`dependencies/`** — внешние библиотеки, подключаемые как git-сабмодули. При клонировании используйте `--recursive`.
- **`docs/`** — включает `CollegeProjectDescription.docx` с полным описанием проекта и `LICENSE.txt` (Apache License).

## 🚀 Сборка и локальная разработка

### Требования

- Компилятор с поддержкой **C++17**.
- **CMake** версии **3.15** или выше.
- (Опционально) **INNO Setup** — только для сборки установщика.

### Клонирование (с сабмодулями)

```bash
git clone --recursive https://github.com/SG123it/CacheCleaner.git
cd CacheCleaner
```

### Сборка через CMake

```bash
# Пример для MinGW
cmake -B build -G "MinGW Makefiles"
cmake --build build
```

Исполняемый файл появится в `build/` (или `build/Release/` в зависимости от генератора).

### Сборка установщика (Windows)

Откройте `setup.iss` в INNO Setup и соберите проект. Готовый дистрибутив будет создан в папке `Output/`.

## ⚙️ Конфигурация (внутренние детали)

### Файлы конфигурации

- **`presets.json`** — основной файл с предустановленными путями для очистки. Скачивается динамически из интернета.
- **`UserPaths.json`** — пользовательский файл с дополнительными путями. Создаётся автоматически или вручную. Пример структуры:

```json
{
  "Paths": [
    "C:\\Users\\%USERNAME%\\AppData\\Local\\Temp",
    "C:\\Windows\\Temp"
  ]
}
```

### Переменные окружения

Поддерживаются переменные вида `$WIN_USERS$`, которые раскрываются в зависимости от контекста системы. При добавлении новых переменных необходимо обновить парсер и документацию.

### Режимы работы

- **`--dry-run-only`** — режим «сухого прогона»: сканирование и вывод списка файлов без удаления. Полезен для отладки и тестирования.

## 🧪 Тестирование и отладка

На данный момент в проекте нет выделенного фреймворка для юнит-тестов. Для проверки логики рекомендуется:

- Использовать режим `--dry-run-only` для анализа поведения без риска удаления данных.
- Добавлять временные логи в ключевых точках (парсинг JSON, обход путей, удаление).
- Проверять работу с различными форматами JSON и путями (включая системные).

При добавлении нового функционала желательно покрывать его хотя бы простыми сценариями ручного тестирования.

## 🔁 CI/CD

Проект использует **GitHub Actions**. Конфигурация находится в `.github/workflows/`. Автоматическая сборка запускается при пуше и пулл-реквестах в основную ветку. Убедитесь, что ваши изменения не ломают сборку.
